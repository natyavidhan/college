# **Data Link and MAC Layer**

The Data Link Layer is responsible for ensuring reliable node-to-node or link-to-link data transfer across a network. It converts raw bits into structured, manageable units called frames, and it implements both flow control and error control mechanisms to ensure data integrity and prevent a fast sender from overwhelming a slow receiver. To handle the complexities of shared communication channels, this layer is commonly divided into two sublayers: the Logical Link Control (LLC) and the Media Access Control (MAC). The LLC sublayer manages error checking, flow control, and network protocol identification, while the MAC sublayer controls how devices access a shared physical medium. The MAC sublayer determines exactly when devices are permitted to transmit data to avoid collisions, and it utilizes physical MAC addressing to uniquely identify devices on the local network segment

### **Data Link Layer Services** 
The primary function of the data link layer is to transform a raw, error-prone physical transmission facility into a reliable line of communication for the network layer. It is responsible for node-to-node (or link-to-link) data transfer across a physical network. To achieve this, it relies on three foundational services: framing, flow control, and error control.

- #### **Framing** 
- Framing is the process of breaking up the continuous bit stream offered by the physical layer into discrete, manageable units called frames. This is conceptually similar to the postal system placing a letter into an envelope to separate one piece of information from another. Each frame generally consists of a header (containing source and destination addresses), a payload field for the data, and a trailer for error detection. Because most local area networks use variable-size framing, the network must clearly define where one frame ends and the next begins. The three primary methods for achieving this are:

	- **Byte Counting:** This approach uses a specific field in the frame header to explicitly state the number of bytes the frame contains. When the receiver reads this byte count, it knows exactly how many bytes to collect to reach the end of the frame. A major drawback to this method (historically seen in the DDCMP protocol) is that if a transmission error alters the byte count field, the receiver loses its synchronization and becomes unable to locate the beginning of subsequent frames.
	- **Byte Stuffing (Character Stuffing):** Used heavily in character-oriented protocols like PPP, this method separates frames by adding a special 8-bit flag byte at both the beginning and the end of the frame. However, binary data (like images or audio) might naturally contain the exact bit pattern of the flag byte. To prevent the receiver from prematurely thinking the frame has ended, the sender uses **byte stuffing**: it inserts a special "escape" character (ESC) immediately before any accidental flag byte in the payload. If the escape character itself naturally appears in the data, the sender stuffs it with a second, preceding escape character. The receiver strips these stuffed bytes out before delivering the data to the network layer.
	- **Bit Stuffing:** Used in bit-oriented protocols like HDLC, this method views the frame strictly as a stream of bits rather than 8-bit characters. Frames are delimited by a special flag bit pattern of `01111110`. To ensure this pattern never accidentally appears within the user data, the sender's hardware monitors the data stream and automatically stuffs a single `0` bit after any sequence of five consecutive `1` bits. When the receiver detects five `1`s followed by a `0`, it automatically destuffs (deletes) the `0` bit to restore the original data.

- #### **Flow Control** 
- Flow control refers to a set of procedures designed to restrict the amount of data a sender can transmit before it must wait for an acknowledgment. It is necessary because a fast, powerful sending computer could easily swamp a slower receiving device by transmitting frames faster than the receiver can process them. If frames arrive too quickly, the receiver is overwhelmed and forced to discard them.

	- **Buffer Management and Feedback:** Flow control is implemented using memory locations called buffers at both the sending and receiving nodes. The data link layer typically relies on feedback-based flow control, where the receiving node sends feedback signals to the sender. If the receiver's buffer fills up, it explicitly tells the sender to stop pushing frames; when buffer vacancies open up, it signals the sender to resume.
	- **Implementation:** Protocols like Stop-and-Wait enforce strict flow control by requiring the sender to transmit just one frame and wait for an acknowledgment before sending the next. More advanced sliding window protocols allow a predefined maximum number of frames to be in transit simultaneously.

- #### **Error Control** 
- Because physical communication channels are subject to noise, attenuation, and interference, frames can be corrupted or lost in transit. Error control in the data link layer ensures data integrity by utilizing mechanisms to detect these errors and request retransmissions, a process collectively known as Automatic Repeat reQuest (ARQ).

	- **Error Detection:** The sender computes a redundant, short token—such as a Cyclic Redundancy Check (CRC)—and appends it to the frame's trailer. Upon arrival, the receiver recomputes the checksum; if its result differs from the checksum inside the frame, the receiver knows the data was corrupted and silently discards the frame.
	- **Timers and Retransmissions:** To recover from dropped frames or lost acknowledgments, the sending data link layer initiates a timer the moment it transmits a frame. If the sender does not receive an acknowledgment before the timer expires, it assumes the transmission failed and retransmits the frame.
	- **Sequence Numbering:** Because a lost acknowledgment causes the sender to retransmit a frame the receiver actually already has, there is a serious risk of the receiver processing duplicate packets. To prevent this, the sender must embed sequence numbers in outgoing frame headers. The receiver checks these sequence numbers to seamlessly distinguish a new frame from a duplicate retransmission

- #### **Error Detection and Correction Techniques:**
	- **Types of Network Errors** Errors during data transmission across a network are typically caused by noise, interference, signal attenuation, or hardware failures. These errors generally fall into the following categories:
	
		- **Single-bit errors:** This occurs when only one bit of a given data unit (such as a byte or packet) is inadvertently changed from 1 to 0, or from 0 to 1.
		- **Multiple-bit errors:** This refers to instances where multiple, non-consecutive bits in a transmitted message are corrupted.
		- **Burst errors:** A burst error means that two or more consecutive bits (or a concentrated cluster of bits) in the data unit have been changed. Burst errors are much more likely to occur than single-bit errors because the duration of an interfering noise signal is typically longer than the duration of a single bit being transmitted.
	
	- **Error-Correcting Codes (Forward Error Correction)** **Forward Error Correction (FEC)** involves adding enough redundant information to the transmitted data so that the receiver can deduce what the original data must have been, even if errors occurred. This strategy is particularly crucial on noisy channels, such as wireless links, where relying on retransmissions would be highly inefficient. Key error-correcting codes include:
	
		- **Hamming Codes:** These are linear block codes that insert redundant parity bits at specific positions (powers of 2, such as 1, 2, 4, 8) within the message. Each parity bit is responsible for checking the parity of a specific subset of the data bits. A standard Hamming code can accurately pinpoint and correct single-bit errors, and it can be designed to detect (but not correct) double-bit errors, a mechanism known as Single Error Correction - Double Error Detection (SEC-DED).
		- **Binary Convolutional Codes:** Unlike block codes, convolutional codes process a sequence of input bits and generate a sequence of output bits based on both the current input and the previous internal state (memory) of the encoder. They are highly effective at handling isolated bit errors and are typically decoded using the Viterbi algorithm, which finds the most likely original sequence of bits.
		- **Reed-Solomon Codes:** These are linear block codes that operate on $m$-bit symbols (often bytes) rather than individual bits. Because a single-bit error and an $m$-bit burst error are both treated simply as one symbol error, Reed-Solomon codes are exceptionally strong at correcting burst errors. They are widely used in DSL, satellite communications, and CDs/DVDs.
		- **Low-Density Parity Check (LDPC) Codes:** In LDPC codes, each output bit is formed from only a small fraction of the input bits, resulting in a matrix representation with a low density of 1s. They rely on an iterative approximation algorithm to decode the received data and offer excellent error-correction performance, making them standard in high-speed 10 Gbps Ethernet and modern 802.11 Wi-Fi.
	
	- **Error-Detecting Codes** Error-detecting codes include just enough redundancy to allow the receiver to determine that an error has occurred, after which the receiver will typically request a retransmission. This method is highly efficient for reliable channels like optical fiber. Common error-detecting mechanisms include:
	
		- **Parity Checks (VRC):** The simplest form of error detection adds a single parity bit to a block of data to ensure the total number of 1s is either even or odd. While simple, parity checks can only detect single-bit errors or an odd number of errors; they completely fail to detect burst errors or an even number of corrupted bits because the errors cancel each other out.
		- **2D Parity (LRC):** Two-dimensional parity extends the basic parity check by arranging data into a grid and adding parity bits both horizontally (rows) and vertically (columns). While it offers better coverage than simple parity, it is still primarily focused on single-bit errors and remains ineffective at detecting or correcting closely grouped burst errors.
		- **Checksums:** This technique involves dividing the message into words (such as 16-bit segments) and creating a running sum of these words using one's complement arithmetic. The one's complement of this sum is appended to the message as the checksum. When the receiver adds all the words together, including the checksum, the result should be zero if no errors occurred. Standard checksums cannot catch errors where chunks of data are simply swapped in order, which is why weighted algorithms like the Fletcher or Adler checksums are sometimes used.
		- **Cyclic Redundancy Checks (CRC):** Also known as polynomial codes, CRCs are highly robust error-detecting codes that view bit strings as polynomials. The sender appends zero bits to the data and divides it by a predefined generator polynomial (the divisor) using modulo-2 arithmetic. The remainder of this division is appended to the data as the CRC. The receiver performs the same division; if the remainder is zero, the data is accepted. CRCs can reliably detect all single-bit errors, double errors, odd numbers of errors, and burst errors up to the length of the CRC code.

- #### **Error Recovery Protocols (Data Link Control)** 
- To ensure reliable data delivery across a network, the data link layer utilizes error recovery protocols that combine flow control and error control, collectively known as Automatic Repeat reQuest (ARQ).

	- **Stop-and-Wait Protocol:** In this simple connection-oriented protocol, the sender transmits a single frame and waits for a positive acknowledgment (ACK) from the receiver before sending the next one. To detect corrupted frames, a checksum or CRC is added to each packet; if a frame is corrupted, the receiver silently discards it. To prevent indefinite waiting if a frame or its ACK is lost, the sender starts a timer when it transmits; if the timer expires before an ACK arrives, it resends a stored copy of the frame. Sequence numbers (modulo-2, simply 0 and 1) are used to help the receiver distinguish between new frames and duplicate retransmissions. While simple, this protocol is highly inefficient for thick and long channels (high bandwidth and long round-trip delays), as it heavily restricts the bandwidth-delay product.
	- **Sliding Window Protocols:** To overcome the inefficiencies of Stop-and-Wait, these protocols use **pipelining**, allowing the sender to transmit multiple frames simultaneously before receiving an acknowledgment. Both sender and receiver maintain imaginary "windows" defining the sequence numbers they are allowed to send or accept.
	    - **Go-Back-N (GBN):** The sender can have multiple unacknowledged frames in transit (up to $2^m - 1$, where $m$ is the sequence number field size in bits), while the receiver window size is strictly 1. The receiver accepts only the exact frame it expects, silently discarding any out-of-order frames. It uses cumulative acknowledgments, meaning an ACK confirms receipt of all frames up to a certain point. If an error occurs or a timer expires for an outstanding frame, the sender "goes back N" and resends that frame along with all subsequent outstanding frames. This can waste significant bandwidth on poor-quality lines.
	    - **Selective-Repeat (SR):** This protocol improves efficiency by only resending the specific frames that were lost or damaged. The receiver window is larger than 1 (specifically, both sender and receiver windows have a maximum size of $2^{m-1}$). This allows the receiver to accept and buffer out-of-order frames until missing frames arrive, after which the complete set is delivered to the network layer. SR uses independent acknowledgments that confirm specific individual frames rather than cumulative sequences.

- #### **Multiple Access Protocols with Collision Detection** 
- When multiple stations share a single broadcast link, a Media Access Control (MAC) protocol is required to coordinate transmissions and handle collisions.

	- **Random Access Methods (ALOHA):** In random access or contention methods, no station is assigned control over another, and there is no scheduled transmission time.
	    - **Pure ALOHA:** A station sends a frame whenever it has data to transmit. If frames overlap, they collide and are destroyed. The sender waits for an ACK; if a timeout occurs, it waits a random backoff time before retransmitting to avoid repeatedly colliding with the same stations. The vulnerable time (the risk window for a collision) is twice the frame transmission time, limiting maximum throughput to about 18.4%.
	    - **Slotted ALOHA:** This improves upon Pure ALOHA by dividing time into discrete slots. Stations are forced to send only at the beginning of a time slot, which halves the vulnerable time and effectively doubles the maximum theoretical throughput to 36.8%.
	- **CSMA (Carrier Sense Multiple Access):** CSMA reduces collisions using a "listen before talk" or "sense before transmit" principle. Stations monitor the medium's energy level before transmitting; however, collisions can still occur because of propagation delay—two stations might sense an idle channel before the other's signal has reached them. Stations follow persistence methods if the channel is busy: **1-persistent** (transmit immediately when idle), **nonpersistent** (wait a random time if busy), or **p-persistent** (transmit with probability _p_ when idle).
	- **CSMA/CD (Carrier Sense Multiple Access with Collision Detection):** Used in classic Ethernet, this protocol augments CSMA by having hardware actively listen to the channel _while_ it is transmitting. If a station detects a collision (the signal on the wire does not match what it is sending), it instantly aborts transmission to save time and bandwidth, and sends a short jamming signal to warn all other stations. Senders then wait a random amount of time determined by a **binary exponential backoff** algorithm before retrying, which dynamically adapts the wait time based on network load. To ensure a station can hear a collision before it finishes transmitting, CSMA/CD imposes a strict minimum frame size based on the network's maximum propagation delay.

- #### **MAC Addressing** 
- Because IP addresses uniquely define endpoints in the broader Internet but do not specify the individual local links a packet must traverse, data-link layers require their own addressing mechanism.

	- Physical addresses (like MAC addresses) change each time a frame moves from one local link to another.
	- An Ethernet MAC address is a 48-bit (6-byte) physical identifier uniquely hardcoded into every network interface card (NIC) by the manufacturer. It is typically represented as 12 hexadecimal digits separated by colons (e.g., 47:20:1B:2E:08:EE).
	- Types of addresses:
	    - **Unicast:** Destined for a single, specific entity (one-to-one communication). In Ethernet, the least significant bit of the first byte is set to 0 (an even hexadecimal digit).
	    - **Multicast:** Destined for a specific group of entities (one-to-many communication). The least significant bit of the first byte is set to 1 (an odd hexadecimal digit).
	    - **Broadcast:** Destined for all entities on the local link (one-to-all communication). The address consists of entirely 1s, represented as FF:FF:FF:FF:FF:FF.

- #### **Ethernet** 
- Originally developed in the 1970s, Ethernet is the most ubiquitous wired LAN technology due to its simplicity, flexibility, and ability to evolve.

	- **Evolution and Generations:**
	    - **Standard Ethernet (10 Mbps):** The first generation of Ethernet running at 10 Mbps. It used CSMA/CD on a shared medium, providing connectionless and unreliable service where corrupted frames were simply dropped.
	    - **Fast Ethernet (100 Mbps):** Kept the same 48-bit addressing and frame formats as Standard Ethernet to guarantee backward compatibility, but increased speeds to 100 Mbps. It heavily utilized star topologies with hubs and switches, and introduced **autonegotiation** so devices could automatically optimize speed (10/100 Mbps) and mode (half/full duplex).
	    - **Gigabit Ethernet (1 Gbps):** Boosted speeds to 1000 Mbps. It predominantly operates in full-duplex mode using switches, completely eliminating collisions and rendering CSMA/CD obsolete. (A rare half-duplex mode exists, which requires carrier extension and frame bursting to maintain the minimum frame size over longer cables).
	    - **10 Gigabit Ethernet (10 Gbps):** Operates exclusively in full-duplex mode with no CSMA/CD. It relies heavily on fiber optic cables and is utilized not just for local LANs, but also for carrier-grade MANs (Metropolitan Area Networks) and wide area applications over distances up to 40 km.
	- **Implementations:**
	    - **10Base5 (Thick Ethernet):** The original bus topology using a thick, stiff coaxial cable (like a garden hose) and external transceivers. It supported cable segments up to 500 meters long.
	    - **10Base2 (Thin Ethernet):** A more affordable bus topology using flexible, thin coaxial cable and BNC connectors, though its maximum segment length was reduced to 185 meters.
	    - **10Base-T (Twisted-pair Ethernet):** A major shift to a star topology. It utilized four unshielded twisted-pair (UTP) cables connecting stations to a central hub or switch, with a maximum distance of 100 meters. This became the dominant form of standard Ethernet because it was easy to maintain and could utilize existing office telephone wiring.

### **Physical Layer**

The Physical Layer is the lowest level of a network architecture, dedicated to the transmission of raw bits over a communication channel via electromagnetic signals. This layer strictly governs the mechanical, electrical, and timing interfaces required to connect devices to transmission media, which can be guided materials like twisted-pair cables and fiber optics, or unguided mediums such as radio waves and satellite links. It defines the exact hardware specifications for network interface cards, hubs, connectors, and voltage levels, along with the modulation techniques used to convert data into transmittable signals. Ultimately, the physical characteristics of this layer—such as bandwidth, signal attenuation, and noise. dictate the absolute maximum data rate and theoretical transmission capacity of the network.

### **Analog and Digital Signals**

- **Data and Signals:** In data communications, information must be transformed into electromagnetic signals to be transmitted. **Analog data** takes on continuous values (like the sound of a human voice), and an **analog signal** similarly has infinitely many levels of intensity over a period of time. By contrast, **digital data** takes on discrete, defined states (like 0s and 1s stored in computer memory), and a **digital signal** has only a limited number of defined values (often simple voltage levels representing 1 and 0).
- **Signal Attributes:** **Periodic analog signals** are built on the fundamental form of a **sine wave**, which is defined by three parameters: **peak amplitude** (highest intensity or voltage), **frequency** (the number of cycles or periods completed in one second, representing the rate of change), and **phase** (the position of the waveform relative to time zero). **Wavelength** is another attribute that binds the period of the wave to the propagation speed of the medium. Conversely, digital signals are usually nonperiodic, so they are described using **bit rate** (the number of bits transmitted in one second, expressed in bps) instead of frequency, and **bit length** (the physical distance one bit occupies on the transmission medium) instead of wavelength.

#### **Maximum Data Rate of a Channel**

- **Theoretical limits:** Every communication channel has a finite transmission capacity, dictated by the available bandwidth and the quality of the channel (noise levels).
- **Nyquist Bit Rate:** In 1924, Henry Nyquist defined the theoretical maximum bit rate for a **noiseless channel**. The formula, $BitRate = 2 \times bandwidth \times \log_2 L$, shows that the maximum data rate depends on the bandwidth and the number of signal levels ($L$) used to represent data. However, increasing the number of signal levels places a heavy burden on the receiver to distinguish between them, which can reduce system reliability.
- **Shannon Capacity:** In 1944, Claude Shannon extended this to **noisy channels**. The Shannon capacity formula is $Capacity = bandwidth \times \log_2 (1 + SNR)$, where SNR is the signal-to-noise ratio. This formula defines the absolute upper limit of a channel's capacity regardless of the number of signal levels used; to exceed it, one must either increase the bandwidth or improve the signal-to-noise ratio.

#### **Transmission Impairment & Performance**

- **Impairments:** Signals degrade as they travel through a medium due to imperfections. **Attenuation** is the loss of energy as the signal overcomes the resistance of the medium, often compensated for by using amplifiers and measured in decibels. **Distortion** occurs when different frequency components of a composite signal travel at different propagation speeds, causing them to arrive out of phase and altering the signal's shape. **Noise** refers to external energy corrupting the signal, including thermal noise (random electron motion), induced noise (from motors or appliances), crosstalk (interference from neighboring wires), and impulse noise (spikes from power lines or lightning).
- **Performance Metrics:**
    - **Bandwidth** can be measured in Hertz (the range of frequencies a channel can pass) or in bits per second (the speed of bit transmission).
    - **Throughput** measures the _actual_ rate at which data is successfully sent through the network, which is often less than the potential bandwidth due to bottlenecks or congestion.
    - **Latency (Delay)** is the total time it takes a message to arrive, calculated as the sum of **propagation time** (distance divided by propagation speed), **transmission time** (message size divided by bandwidth), **queuing time**, and **processing delay**.
    - **Jitter** is the variation in packet arrival times, which severely impacts time-sensitive real-time applications like audio and video.
    - **Bandwidth-Delay Product** calculates the volume of the link (bandwidth $\times$ delay), defining the maximum number of bits that can fill the link at any given time.

#### **Transmission Media**

- **Guided (Wired) Media:** These provide a physical conduit for the signal. **Twisted-Pair Cable** consists of two insulated copper wires twisted together to balance out electromagnetic interference and crosstalk; it comes in unshielded (UTP) and shielded (STP) varieties. **Coaxial Cable** features a central conductor surrounded by an insulating layer and an outer metal shield, allowing for higher bandwidths than twisted-pair but suffering from rapid signal attenuation over distance. **Fiber-Optic Cable** transports signals using pulses of light through a glass or plastic core surrounded by cladding, utilizing total internal reflection to achieve massive bandwidths, low attenuation, and complete immunity to electromagnetic noise.
- **Unguided (Wireless) Media:** These transport electromagnetic waves through free space. **Radio Waves** (3 kHz to 1 GHz) are omnidirectional, meaning they travel in all directions and can penetrate walls, making them ideal for AM/FM radio and television broadcasting. **Microwaves** (1 to 300 GHz) are unidirectional and require line-of-sight propagation with strictly aligned antennas; they cannot easily penetrate walls and are heavily used for cellular phones, satellite networks, and wireless LANs. **Infrared Waves** (300 GHz to 400 THz) are used for short-range, line-of-sight communication (like TV remote controls or PC peripherals) and cannot penetrate solid objects, which naturally prevents interference between adjacent rooms.

#### **Satellite Communication** 
Satellites act as massive microwave relays in space, utilizing bidirectional antennas to cover specific geographic areas called footprints.

- **Geostationary Earth Orbit (GEO)** satellites orbit at approximately 35,800 km, matching the Earth's rotation so they appear stationary. However, this high altitude introduces a significant propagation delay.
- **Medium-Earth Orbit (MEO)** satellites orbit between the two Van Allen belts (e.g., around 18,000 km) and are famously utilized for the Global Positioning System (GPS).
- **Low-Earth Orbit (LEO)** satellites orbit much closer to Earth (e.g., 750 to 1400 km), meaning they have low propagation delay. They are grouped in constellations (like Iridium or Globalstar) to provide seamless global coverage for mobile phones and broadband internet.

#### **Multiplexing** 
Multiplexing allows the simultaneous transmission of multiple signals across a single link when the link's bandwidth exceeds the needs of individual devices.

- **Frequency-Division Multiplexing (FDM):** An analog technique that divides the total available bandwidth of a link into several distinct frequency bands. Each source modulates its signal onto a different carrier frequency, and these channels are separated by unused "guard bands" to prevent overlapping.
- **Wavelength-Division Multiplexing (WDM):** Essentially FDM applied to optical fibers at very high frequencies. It combines multiple beams of light of different colors (wavelengths) onto a single fiber using an optical multiplexer (like a prism) to achieve immense data rates.
- **Time-Division Multiplexing (TDM):** A digital technique where the link's bandwidth is shared by dividing time into slots. Each connection occupies a distinct time slot to transmit its digital signal. In _synchronous TDM_, slots are pre-assigned even if a station has nothing to send, whereas _statistical TDM_ dynamically allocates slots only to active connections to improve efficiency.

#### **Signal Conversion/Modulation**

- **Digital-to-Digital (Line/Block Coding):** **Line coding** converts a sequence of binary bits into a digital signal (e.g., using voltage levels like in NRZ, or mid-bit transitions like in Manchester encoding). **Block coding** improves this by adding redundancy (e.g., converting 4 bits into a 5-bit block in 4B/5B encoding) to ensure synchronization and provide inherent error detection.
- **Analog-to-Digital (Pulse Code Modulation - PCM):** Digitizes an analog signal (like voice) through three steps: **Sampling** the signal at regular intervals (at least twice the highest frequency, per the Nyquist theorem), **Quantizing** the sampled amplitudes into discrete levels, and **Encoding** those levels into a binary bit stream.
- **Digital-to-Analog (Modulation):** When only an analog bandpass channel is available, digital data must modulate a high-frequency carrier signal. This can be done by varying the amplitude (**Amplitude Shift Keying, ASK**), varying the frequency (**Frequency Shift Keying, FSK**), or varying the phase (**Phase Shift Keying, PSK**). The most efficient and widely used method is **Quadrature Amplitude Modulation (QAM)**, which alters both the amplitude and the phase simultaneously to pack multiple bits into a single signal element.
